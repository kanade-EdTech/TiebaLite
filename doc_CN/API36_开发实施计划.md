# Tieba Lite API 36 开发实施计划

> 制定日期：2026-10-03  
> 关联方案：[Android API 36 安全适配与功能优化方案](./Android_API36_安全适配与功能优化方案.md)  
> 代码基线：`4e96c26ecbdfd81d9ddffba1eb3a3f1d2a455163`  
> 最终目标：完成安全整改、构建系统现代化和 Android 16（API 36）适配，并形成可灰度发布的稳定版本。

## 1. 执行策略

### 1.1 总体原则

1. 不在同一个变更中同时升级构建工具、Target API 和业务架构。
2. 每个阶段必须先建立基线，再修改，再执行回归。
3. 安全问题优先于功能优化；P0 问题未清零时不得发布。
4. `compileSdk` 与 `targetSdk` 分开升级，先解决编译兼容，再逐级启用平台行为。
5. 数据迁移必须支持覆盖安装，不得要求用户清除应用数据。
6. 每项改造都应可独立回滚，禁止超大提交。
7. 认证、发帖、回复、删除、签到等写操作必须避免重复执行。

### 1.2 推荐执行模型

- GPT-5.6 Sol：实现、编译、测试、修复和提交整理。
- Opus 5.5：阶段开始前审查方案，阶段结束后复核安全性和架构偏差。
- 人工确认：登录、发帖、回复、签到、通知、隐私政策和正式签名构建。

### 1.3 分支与提交约定

建议从基线创建长期迁移分支：

```text
codex/api36-migration
```

每个里程碑使用独立子分支，完成验收后合入迁移分支：

```text
codex/m0-baseline
codex/m1-security
codex/m2-build-modernization
codex/m3-api31-33
codex/m4-api34
codex/m5-api35
codex/m6-api36
codex/m7-architecture
codex/m8-release
```

提交建议采用以下粒度：

- 一项安全修复一个提交；
- 一类 API 行为变更一个提交；
- 一次依赖升级一个提交；
- 自动格式化与功能修改分开提交；
- 数据迁移代码和迁移测试放在同一个提交中。

## 11. M8：发布准备

### 11.1 自动化门禁

- Debug 和 Release 构建通过。
- 单元测试、迁移测试和关键 UI 测试通过。
- Android Lint 无 Error。
- 依赖漏洞扫描无未处理的高危或严重漏洞。
- Release APK/AAB 不包含测试端点、调试证书或明文秘密。
- R8 后核心功能正常。

### 11.2 人工验收

- 登录、切换账户、退出；
- 首页、论坛、帖子、楼中楼；
- 搜索、收藏、消息；
- 发帖、回复和删除操作；
- 图片选择、上传、保存和分享；
- 自动签到、手动签到和任务状态；
- 通知允许、拒绝和关闭渠道；
- WebView 登录、外链和恶意 URL；
- 深色模式、横屏、分屏和大屏；
- 全新安装、覆盖安装和账户数据迁移。

### 11.3 灰度策略

建议采用分阶段放量：

```text
内部测试 → 5% → 20% → 50% → 100%
```

每个阶段至少观察：

- Crash-free users；
- ANR；
- 启动失败率；
- 登录失败率；
- API 401/403/429/5xx；
- WebView 错误率；
- 签到成功率；
- WorkManager 重试和取消率；
- 数据迁移失败率。

发现以下情况应停止放量并回滚：

- 崩溃率明显高于旧版本；
- 登录凭据、Cookie 或用户数据泄漏；
- 数据库迁移造成数据丢失；
- 发帖、回复、删除等写操作重复执行；
- WebView 白名单或 Bridge 隔离失效；
- 自动签到造成高频请求或账户异常。

## 12. 发布阻断门禁

发布前必须全部满足：

- [ ] Cookie、BDUSS、STOKEN 不出现在日志、备份和明文数据库中。
- [ ] 所有认证流量均使用 HTTPS。
- [ ] 非白名单页面无法获取 Cookie、执行注入脚本或访问 JS Bridge。
- [ ] 所有 PendingIntent 均声明正确的可变性。
- [ ] 所有导出组件均经过逐项审查。
- [ ] 所有内部动态 Receiver 均为 `RECEIVER_NOT_EXPORTED`。
- [ ] 通知、图片选择和存储不依赖过时权限。
- [ ] Edge-to-Edge 在主要页面无内容遮挡。
- [ ] 预测性返回不会丢失数据或打乱导航栈。
- [ ] 数据迁移有自动化测试并通过覆盖安装验证。
- [ ] 后台任务支持延迟、重试、取消和幂等。
- [ ] API 21、29、31、33、34、35、36 测试结果已记录。
- [ ] AAB 已通过 Play 预发布报告或等效测试。

## 13. 首批建议执行任务

第一批只处理可独立验证且风险最高的事项：
