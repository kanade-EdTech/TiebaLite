## 4. CI 基线

新增 `.github/workflows/m0-baseline.yml`，在 Push 和 Pull Request 时执行：

1. 先使用 JDK 17 初始化新版 Android SDK 工具并安装 API 29、Build Tools 28.0.3，再切换 JDK 8 构建旧版 Gradle 项目；
2. 单元测试与 Debug APK 构建；
3. Lint 报告生成；
4. 在 Linux/KVM 模拟器上分别执行 API 29、API 36 安装和冷启动冒烟测试；
5. 上传 APK、测试报告、Lint 报告、设备截图、Activity 状态、包信息和 Logcat。

由于存在已确认的基线 Lint Error，Lint 步骤暂时标记为允许失败，但报告不会被隐藏。修复全部已确认的 Lint Error 后应移除该豁免，使 Lint Error 成为合并阻断门禁。

- 已从 Android 官方安装 `system-images;android-29;google_apis;x86_64` revision 13。
- 已从 Android 官方安装 `system-images;android-36;google_apis;x86_64` revision 7。
- `emulator-check accel` 确认 WHPX 可用。
- 两个 AVD 均能定位系统镜像并通过模拟器兼容性检查。
- Emulator 36.5.11 启动 QEMU 时未自动传递 `bios-256k.bin` 搜索路径；将 BIOS 临时映射到英文路径后可越过该错误。
- 越过 BIOS 错误后，API 29 长时间停留在 ADB `offline`；API 36 在 WHPX 下报告 QEMU CPU 和主循环线程挂死。
- 关闭 WHPX 改用软件仿真后，API 36 仍出现相同 QEMU 线程挂死，达到两轮诊断上限。
- 该问题对两个 API 一致，归类为宿主测试环境问题，不归类为应用缺陷或 API 36 迁移回归。
- 诊断进程和项目内临时 AVD/BIOS 文件已清理，无本地临时产物残留。
